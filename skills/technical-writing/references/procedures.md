# Procedures

Write instructions as commands. Put the condition or warning before the action it governs. Put common cases before exceptions.

Give one instruction per sentence. State the expected output or observable result when the reader needs it to continue. Use real commands and name the actor when behavior might otherwise be unclear.

Keep articles such as "the" and "a." Use one verb for one action throughout the procedure. Avoid ambiguous "-ing" constructions when a direct verb works.

Review instructions longer than about 20 words and other sentences longer than about 25. These are signals to inspect, not mechanical limits. Keep a longer sentence when it expresses one clear condition and action better than a split.

Use present tense for current behavior. Do not describe a difficult operation as "simply," "easy," or "quickly." Put optional branches where the reader can skip them. Keep warnings specific to an actual hazard.

Preserve syntax and repository indentation in command and code examples. Distinguish commands to run from output to expect.

Sources: [Google developer style](https://developers.google.com/style) and transferable principles from [ASD-STE100](https://asd-ste100.org/), Issue 9, 2025, consulted 2026-07-18. These notes do not establish formal STE compliance.
