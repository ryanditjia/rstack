# Document structure

Choose the mode for the reader's purpose. A README may contain several clearly separated sections; do not split useful navigation merely to enforce one mode per file.

| Reader needs | Mode |
| --- | --- |
| Learn through doing | Tutorial |
| Complete a known task | How-to |
| Look up facts | Reference |
| Understand a bounded why question | Explanation |

Tutorials open with what the learner builds. Give visible results early and state what the learner should see after each step. Keep background short and link explanations that would interrupt progress.

How-to guides solve the reader's problem. Assume competence, give the actions, and allow conditional branches. Name the guide for the task. Move teaching and background to linked material.

Reference mirrors the thing described. State supported options, defaults, limits, and errors. Generate facts from authoritative code where practical. Distinguish verified behavior from unknowns; a reference format is no reason to invent certainty.

Explanation connects a real why question to constraints, history, alternatives, and tradeoffs. Give your assessment where evidence supports it. Keep the topic bounded.

Separate modes where mixing them interrupts the reader's purpose, then link them. Task headings use verb phrases; concept headings name the concept. Use sentence case and a navigable heading hierarchy. Use numbered lists for sequences, bullets for parallel items, and meaningful link labels.
