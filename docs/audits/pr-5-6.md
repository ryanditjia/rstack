# PRs 5 and 6 audit

Rstack keeps pstack's evidence and verification requirements while letting Astra choose how much delegation the task needs. This audit covers [PR #5](https://github.com/ryanditjia/rstack/pull/5), the repository-evidence rewrite of `why`, and [PR #6](https://github.com/ryanditjia/rstack/pull/6), the mode consolidation and architecture changes. PR #6 carries the corrections from both audits.

The upstream baseline is [pstack at efa2a53](https://github.com/cursor/plugins/tree/efa2a531985e0a8084d36ff3cf87233be8a9f34b/pstack). This is a review of the affected workflows, not a claim that every rstack skill matches current upstream.

## Findings and resolutions

| Finding | Resolution in PR #6 |
| --- | --- |
| PR #5 preserved confidence tiers, contradictions, repository archaeology, threshold tracing, co-change analysis, issue scope history, and incident linkage. | Retain those files and their existing wording. Vendor connectors remain opt-in, as requested. |
| PR #5 no longer explicitly distinguished unavailable or unsearched sources from searches with no results. | Restore that distinction in the `why` entry, investigator prompt, and synthesis checklist. Report only relevant missing sources, without discovering connectors. |
| Delegated investigators lost explicit query recording and counterfactual checks, though the parent's epistemics retained the latter. | Restore exact queries, scope, author/date, relevance, and the alternative-explanation check in the investigator prompt. |
| PR #6's permissive orchestration introduction conflicted with mandatory implementation delegation and agent counts in routed playbooks. | Make Astra's direct-work default authoritative for routed staffing instructions. Start with one delegate and expand for a named need. Preserve independent review and explicit requests for multi-model workflows. |
| Feature, Bug fix, and Refactoring forced delegates even when the parent could implement the change. | Allow direct implementation with a reviewer who did not write the change. A parent may review a delegate's implementation. |
| The architect rewrite made concrete alternatives conditional. | Require two structurally distinct shapes, or a concrete rejected alternative and the constraint that rules it out. The parent can do the comparison. |
| The mode duplicated principle descriptions and prose rules, and required verbatim plan copying and empty throughput reports. | Remove the duplicate catalog and prose instructions. Keep the standalone principles, focused writing skills, required evidence, verification gates, and substantive delegation decisions. |
| The standard typecheck covered only `watch-pr`, despite changes to `orch`. | Add a root tools tsconfig that includes both directories and point the typecheck command at it. |
| The portability scan rejected retired tools in prose but skipped TypeScript. | Scan `.ts` and `.tsx` too, excluding installed dependencies. |

## Intentional differences and limits

Repository evidence replaces automatic connector discovery. Standalone `arena` and `interrogate` retain their explicit multi-model workflows. When rmode routes into them, its staffing policy applies while their comparison rubrics and independent-review requirements remain.

Shipping uses GitHub's native atomic stack merge instead of upstream's one-PR-at-a-time procedure. The installed `gh-stack` v0.1.0 help confirms the atomic operation and inclusion of every PR below the selected ceiling. No merge was performed during this audit. This is a previously adopted delivery adaptation, not a token-saving change.

No token-budget experiment or fresh-thread behavioral evaluation was run. Word counts describe instruction size only. The criteria map is a manual semantic review, and the tool tests verify executable behavior; neither proves identical agent outcomes or 80% token savings.

The frontier parser has fixture-based CLI coverage. A live `gh stack view --json` on this branch reports that the branch is not part of a stack. Live parser integration remains unverified; the audit does not treat the fixture tests as a live stack run.
